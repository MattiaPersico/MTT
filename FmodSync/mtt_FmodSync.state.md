## Works (tested in REAPER/FMOD 2.04)
- Connection to FMOD Studio's Script Server (TCP 3663), auto-reconnect every 3 s; answers framed by markers via `studio.system.print`.
- Link of the RPP to the .fspro open in FMOD; per-user .fspro path in ExtState; config in `<rpp>.fmodsync.json`.

## Written, waiting for a test in REAPER
- No rounded corners in both windows (all Rounding style vars 0, icon hover square). Mini empty text: "No asset selected." / "No assets in this project."
- Adopt for a file under another prefix ("similar") is no longer one click: the cell shows a grey "Similar?" that opens "Same sound?" (both names, folders, channels side by side). "Adopt this take" renames and links that take only (its own folder, no cascade); "Not the same sound" is remembered per take (takes[key].not_similar). Not proposed at all when the take's own prefix differs from the file's (Enemies_A_..._Walk_01 vs Enemies_B_..._Walk_01) or FMOD's channelCount differs. Same-name "found" keeps its Adopt button. Only when cfg.legacy is true: asked once in a window when the project is linked ("Did this project already send files to FMOD before FMOD Sync?"); unset counts as no; no setting for it (user found it confusing); otherwise those takes are plain "none" (Link).
- Folder picker suggestions also come from FMOD files with the take's "<track>_<NN>" under another prefix: their folder, with the prefix word that names a folder swapped for this take's (Characters/NPCs/Enemies/JanuaryMilestoneEnemy/Fx/Foley -> .../MCSF_Assault/Fx/Foley), else that folder as is. Up to 4 suggestions.
- FMOD folders: FMOD keeps each asset folder as an EncodableAsset (assetPath "a/b/", Metadata/Asset/*.xml). A script cannot make one (create gives an empty one: assetPath ignores setValue; MasterAssetFolder.getAsset finds nothing; tried in FMOD 2.04 on 2026-11-20; setAssetPath on a new one would move the whole Assets folder: its getAbsoluteAssetPath is the Assets folder). Writing the XML was turned down: no source control work in this script (user's rule). So folders made by a sync or Move stay #unimported and the report asks for Import Contents.
- Answers from FMOD are no longer fully URI-encoded: only non-printable-ASCII, "@" and "%" are escaped, so what FMOD's console shows is about a third as long.
- Drag to FMOD (macOS): a first column of drag handles (six dots) in both tables. Hovering a Linked take's handle writes its rect (Cocoa coords via PointConvertNative) and FMOD file paths (all selected Linked takes when the row is selected) to $TMPDIR/mtt_fmodsync_drag.cmd; a helper process (mtt_fmodsync_drag.js, osascript JXA + AppKit, started on the first hover, quits 3 s after the script stops rewriting the file) puts a native borderless window exactly over the handle, so the press lands in it and drags the files in one gesture. Files come from FMOD's Assets folder: FMOD links a file dropped from there to its asset, no copy (checked by the user). The window is fully transparent (the user grabs REAPER's dots). Its timer runs in NSRunLoopCommonModes (in the default mode it stopped after a drag, leaving a stale window with old paths); tick errors go to $TMPDIR/mtt_fmodsync_drag.ack.log. The script pkills leftover helpers at start and before a relaunch. A drop of 4 files into FMOD worked; the lifecycle fix is untested. Windows not done (PowerShell WinForms DoDragDrop could do it). JXA limits found: overriding acceptsFirstMouse:/hitTest:/endedAtPoint: fails (types), NSAttributedString init is undefined, layer CGColor crashed.
- Take table: one row per file to render (takes of every top-level folder track; tracks with no take are not shown). Columns File, Ch, Status, sortable by header; not resizable (File takes the free width).
- File name = name template with wildcards ($project $title $author $track $item $index); default `$track_$index`, project default in Settings, per-take rename in the panel under the table (empty = project default). ("Same line" removed in 0.2.)
- Status: Linked (same file name in its folder), New (folder set, not in FMOD), Adopt (same name elsewhere = moved, or a file ending with `<track>_<NN>` under another prefix: Adopt renames the take to match), Link (folder picker). A take with no folder whose exact name is in exactly one FMOD folder is linked on its own.
- Selection: click, Shift range, Cmd/Ctrl toggle; the time selection follows the selected takes and the edit cursor goes to the start of the take clicked.
- Panel under the table: name and FMOD folder of the selected takes; render settings of their assets (channels auto/1-8, sample rate (default: the project's), tail (default 0), 2nd pass (default off), normalize to a LUFS-I value and brickwall limiter at a dB ceiling (both off by default)), Reset, Render.
- Tail suggested from reverbs (2026-11-23, untested): Tail is a checkbox + seconds like Normalize; off = tail 0 (default) and the field shows the suggestion, ticking it takes each asset's own suggestion (never turns on by itself). render.reverb_tail(folder_track): enabled online FX on the folder track and every track under it whose name has reverb/verb/room/hall/plate/spring/chamber/convol/shimmer/... (not delay/echo/room EQ unless "verb"); decay = formatted value of the first param named decay/rt60/reverb time/tail/length/time/space (not pre/early/mod/damp/low/high...; ms -> s, bare number > 30 = ms) + pre-delay; only a Room Size param (ReaVerbate) -> 0.5 + 4.5*size; unreadable (ReaVerb IR) -> 2 s. Longest of them, rounded up to 0.1 s; re-read at most once a second. No reverb: ticking sets 1 s. Tooltip lists the reverbs found. Sends to reverb buses outside the folder and take FX are not looked at.
- Render settings are per asset (`assets[guid].render`); every take of an asset renders with them. Overrides (2026-11-23, untested; mattia's rule): with takes selected (or items selected in REAPER) a change goes to those takes, takes[key].render (false = off/auto/project's, wins over the track's on); with no take selected it goes to the track, assets[guid].render (full window: the panel then shows the takes of the tracks selected in REAPER, title "Track X"; Mini: no take clicked). A take's value always wins. (The "Use track settings" button was removed in 0.2.) A setting's label is orange (COL_ACCENT) when a selected take has its own value for it. Project render defaults (2026-11-23, untested): Settings > Render defaults (Ch, rate, tail, 2nd pass, normalize, limiter) in cfg.render_defaults (only values differing from built-in); order project < track < take; a track value equal to the project default is not kept, a track Auto/off over an on default is stored as false. With no take selected, labels are orange where a track has its own value. Ch in the table gets "*" for either. Old takes[key].channels moves into takes[key].render on load.
- Full-screen button next to the window's close button and double click on the title bar (as in mtt_MetadataAssistant).

- Rename / Move mismatch (tested with FMOD 2.04): each take remembers the FMOD file it was last linked to (`takes[key].linked`); when its name or folder changes here and that file is still in FMOD, Status shows Rename / Move / Move+Rename, which calls `AudioFile.setAssetPath` and renames the file already rendered. "Use" in the folder picker moves the takes already in FMOD on its own. Not tested with Perforce.

- Folder picker: browser with breadcrumb, "..", search, folders holding these names in orange; "New folder" stays virtual until a file is moved into it. FMOD tags a folder made by setAssetPath #unimported and the API has no way to import a folder: after such a Move the script tells the user to run Import Contents on it.

- Take markers in renders (2026-11-23, file writing tested on a synthetic WAV, untested in REAPER): REAPER's "embed take markers" flag (&1024) did not show up in FMOD or Soundminer, so it was dropped. Markers on child-track items are not taken. Failures go to the render report. Full and Mini.

## Mini view (written, waiting for a test)
- Layout for a short dock (font 13, tighter spacing): the list (File, Status) at the left, at its right Name + Default, Folder, Ch and a "Render settings" button ("*" when the assets override any) that opens a popup with sample rate, tail, 2nd pass, normalize, limiter; bottom right the FMOD state dot (click = read FMOD again), Render (N) and the gear; no footer, no title line. List over settings when the dock is narrow. No take clicked = settings and Render apply to every take shown; a click narrows to that take, a second click goes back to all.
- FMOD request errors show in the footer (orange, tooltip with the error) and clear on the next answer; the time REAPER spends rendering no longer counts against a request's 15 s.
- Muted items count for nothing: child-item blocks are made of unmuted items only (and so are their time bounds); a muted folder item, or a folder item with no unmuted child item under it, is no take.
- Item selection: when the items selected in REAPER change, the takes they belong to (an asset's folder item; for a child item, the take whose time range it overlaps) become the selection, in both windows. Mini shows the takes of the assets of the selected tracks and of the selected items; with no item selected any more it goes back to all of them.
- Folder picker "Suggested": up to 3 folders from how the other assets of this RPP are placed (a folder part equal to their track name, or last parts equal to their last "_" words, becomes this track's; else their folder as is), assets sharing more leading words first; an FMOD folder named as the track (or its last word) first of all. Applied per asset when several are picked; a folder FMOD lacks is virtual "(new)" until a Move.
- Sync after every render (written, waiting for a test): Linked takes overwrite FMOD's file (absolute path from `getAbsoluteAssetPath`, plain file copy; fails on read-only Perforce files that are not checked out), then the RefreshModifiedAssets action if it exists; New takes are imported (`studio.project.importAudioFile`, copied to the Assets root) and moved with `setAssetPath`. Other statuses are reported as not synced. Status "Not rendered" (grey) = New with no file in the render folder.
